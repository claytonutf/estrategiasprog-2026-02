01 · Fundamentos

O que é uma tabela Hash?

A ideia é transformar uma chave em um índice de um array, permitindo localizar rapidamente a posição associada à informação.

Da busca por comparação ao acesso direto

Muitos métodos de busca procuram uma informação comparando suas chaves. Em estruturas ordenadas, algoritmos eficientes podem chegar a O(n log n) considerando a ordenação, enquanto uma busca binária pode operar em O(log₂ n).

Uma busca ideal seria aquela em que a posição do elemento pudesse ser obtida diretamente, sem uma sequência de comparações. Nesse cenário, o custo é O(1).

Por que o array sozinho não resolve?

Arrays permitem acessar uma posição por índice em O(1). O problema é descobrir qual índice contém a informação desejada quando temos apenas uma parte de seus dados, isto é, sua chave.

Ideia da Hash: usar uma função para calcular o índice a partir da chave.
posição = função_de_hashing(chave)

03 · Colisões

O que é uma colisão?

Uma colisão ocorre quando duas ou mais chaves diferentes produzem a mesma posição.

Exemplo

Suponha uma tabela com 10 posições e uma função simplificada:

h(chave) = chave mod 10

As chaves 23 e 43 produzem:

23 mod 10 = 3     43 mod 10 = 3

As duas querem ocupar o índice 3. Isso é uma colisão.

Colisão não significa falha

A colisão é indesejável porque pode diminuir o desempenho, mas é uma situação prevista no projeto de tabelas Hash.

  • Uma boa função de hashing reduz a concentração de chaves.
  • O método de tratamento de colisões determina como os elementos serão acomodados.
  • No pior caso, muitas colisões podem levar a custo O(n).

Distribuição direta

Cada chave é direcionada para uma posição livre. É o cenário ideal para uma distribuição uniforme.

Endereçamento aberto

Quando a posição calculada está ocupada, a implementação procura outra posição segundo uma estratégia de sondagem. Exemplos comuns incluem sondagem linear e quadrática.

Encadeamento

Cada posição pode apontar para uma estrutura que armazena vários elementos que produziram o mesmo índice, como uma lista encadeada.

04 · Aplicações

Onde tabelas Hash são utilizadas?

Busca de elementos

Estruturas em memória, bancos de dados e mecanismos de busca podem utilizar técnicas baseadas em hashing.

Integridade de dados

Um resumo calculado a partir dos dados pode ser comparado posteriormente para detectar alterações ou erros de transmissão.

Senhas

Sistemas de autenticação podem armazenar derivados criptográficos das senhas em vez das senhas em texto puro.

Compiladores

Tabelas de símbolos são uma aplicação clássica de estruturas de associação entre identificadores e informações.

Criptografia

Funções de hash criptográficas aparecem em aplicações de integridade e segurança. O material-base cita MD5 e a família SHA.

Estruturas de dados

A técnica é especialmente útil quando o problema exige associar uma chave a um valor e realizar consultas frequentes.

Tipo opaco: no cabeçalho, o programador conhece Hash, mas a definição de struct hash fica na implementação. Assim, no main(), pode-se declarar Hash *ha; sem expor os campos internos.

Por que usar um array de ponteiros?

O material explica que a tabela armazena endereços das estruturas de alunos, e não cópias das estruturas diretamente em todas as posições do array. Como muitas posições podem permanecer vazias, o array de ponteiros evita ocupar espaço com estruturas completas em posições sem elementos.

06 · Memória dinâmica

Criando a tabela Hash

A criação envolve duas alocações principais: uma para a estrutura que representa a tabela e outra para o array de ponteiros itens. Cada posição começa com NULL.

Implementação didática de criaHash
Hash* criaHash(int TABLE_SIZE) {
    Hash* ha = (Hash*) malloc(sizeof(Hash));

    if (ha != NULL) {
        int i;

        ha->TABLE_SIZE = TABLE_SIZE;

        ha->itens = (struct aluno**) malloc(
            TABLE_SIZE * sizeof(struct aluno*)
        );

        if (ha->itens == NULL) {
            free(ha);
            return NULL;
        }

        ha->qtd = 0;

        for (i = 0; i < ha->TABLE_SIZE; i++)
            ha->itens[i] = NULL;

        return ha;
    }

    return NULL;
}

Campos da estrutura

  • TABLE_SIZE: tamanho da tabela.
  • qtd: quantidade de elementos armazenados.
  • itens: array de ponteiros para os elementos.

Escolha do tamanho

O material recomenda, como regra didática, preferir um número primo e evitar potências de dois, pois isso pode contribuir para uma distribuição mais adequada quando se utilizam funções de hashing simples.

07 · Gerenciamento de memória

Destruindo a tabela Hash

Ao destruir a tabela, é necessário liberar os elementos armazenados, depois o array de ponteiros e, por fim, a própria estrutura da tabela. A ordem é importante para evitar vazamentos de memória.

liberaHash
void liberaHash(Hash* ha) {
    if (ha != NULL) {
        int i;

        for (i = 0; i < ha->MAX; i++) {
            if (ha->itens[i] != NULL)
                free(ha->itens[i]);
        }

        free(ha->itens);
        free(ha);
    }
}
Atenção: no código da figura, o campo utilizado no laço aparece como MAX, enquanto a estrutura apresentada anteriormente usa TABLE_SIZE. Em uma implementação real, esses nomes precisam ser consistentes. A página preserva a ideia da figura e destaca essa diferença para fins didáticos.
08 · Função de hashing

Calculando a posição da chave

A função de hashing é utilizada tanto na inserção quanto na busca para determinar a posição em que um elemento deve ser armazenado ou procurado.

Simples

Deve ser simples e barata de calcular.

Boa distribuição

Deve espalhar as chaves pelas posições disponíveis de maneira equilibrada.

Baixa concentração

Quanto menos concentração desnecessária houver em determinadas posições, menor tende a ser o impacto das colisões.

Observação importante: a condição “valores diferentes produzem posições diferentes” é uma propriedade desejável, mas, para uma tabela de tamanho finito, não pode ser garantida para todas as chaves possíveis quando o universo de chaves é maior que o número de posições. Por isso, colisões precisam ser tratadas.

Exemplo simples com módulo

h(k) = k mod TABLE_SIZE

Se TABLE_SIZE = 11 e k = 42, então:

h(42) = 42 mod 11 = 9

Logo, o elemento será direcionado inicialmente para a posição 9.

09 · C na prática

Uma implementação mínima e didática

A seguir, uma versão simplificada que demonstra a ideia de uma tabela Hash com alunos e endereçamento direto, sem tratar colisões. Ela complementa as figuras e facilita o entendimento dos componentes.

TabelaHash.h
#ifndef TABELAHASH_H
#define TABELAHASH_H

typedef struct aluno {
    int matricula;
    char nome[30];
    float n1, n2, n3;
} Aluno;

typedef struct hash Hash;

Hash *criaHash(int tamanho);
void liberaHash(Hash *ha);

int valorString(char *str);
int insereHash_SemColisao(Hash *ha, Aluno al);
int buscaHash_SemColisao(Hash *ha, int mat, Aluno *al);

#endif
TabelaHash.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include "TabelaHash.h"

struct hash {
    int qtd;
    int TABLE_SIZE;
    Aluno **itens;
};

Hash *criaHash(int tamanho) {
    Hash *ha = malloc(sizeof(Hash));

    if (ha == NULL)
        return NULL;

    ha->TABLE_SIZE = tamanho;
    ha->qtd = 0;

    ha->itens = malloc(tamanho * sizeof(Aluno *));

    if (ha->itens == NULL) {
        free(ha);
        return NULL;
    }

    for (int i = 0; i < tamanho; i++)
        ha->itens[i] = NULL;

    return ha;
}

void liberaHash(Hash *ha) {
    if (ha == NULL)
        return;

    for (int i = 0; i < ha->TABLE_SIZE; i++)
        free(ha->itens[i]);

    free(ha->itens);
    free(ha);
}

int valorString(char *str) {
    int valor = 0;

    for (int i = 0; str[i] != '\0'; i++)
        valor = 31 * valor + (unsigned char) str[i];

    return valor;
}

int insereHash_SemColisao(Hash *ha, Aluno al) {
    int pos = al.matricula % ha->TABLE_SIZE;

    if (ha->itens[pos] != NULL)
        return 0;

    Aluno *novo = malloc(sizeof(Aluno));

    if (novo == NULL)
        return 0;

    *novo = al;
    ha->itens[pos] = novo;
    ha->qtd++;

    return 1;
}

int buscaHash_SemColisao(Hash *ha, int mat, Aluno *al) {
    int pos = mat % ha->TABLE_SIZE;

    if (ha->itens[pos] == NULL)
        return 0;

    if (ha->itens[pos]->matricula != mat)
        return 0;

    *al = *ha->itens[pos];
    return 1;
}
Nota: essa versão é propositalmente simples. A função de inserção rejeita a operação quando a posição já está ocupada. Em uma tabela Hash completa, deve-se escolher e implementar uma estratégia de tratamento de colisões.
main.c
#include <stdio.h>
#include "TabelaHash.h"

int main(void) {
    Hash *ha = criaHash(11);

    if (ha == NULL)
        return 1;

    Aluno a = {101, "Ana", 8.0, 9.0, 8.5};
    Aluno b = {202, "Bruno", 7.0, 8.0, 9.0};

    insereHash_SemColisao(ha, a);
    insereHash_SemColisao(ha, b);

    Aluno encontrado;

    if (buscaHash_SemColisao(ha, 202, &encontrado))
        printf("Encontrado: %s\n", encontrado.nome);

    liberaHash(ha);

    return 0;
}

Para C++, a mesma ideia pode ser representada com classes, templates e containers da biblioteca padrão, como std::unordered_map. O material-base, porém, apresenta a implementação modular em C.

11 · Síntese

O que você deve lembrar?

Chave
É a informação utilizada para localizar o elemento.
Função de hashing
Transforma a chave em uma posição da tabela.
Tabela
É um array que representa as posições disponíveis.
Colisão
Acontece quando chaves diferentes resultam na mesma posição.
Desempenho
No caso médio, a busca pode ser O(1); no pior caso, pode chegar a O(n).
Memória
Em C, é fundamental liberar os elementos, o array de ponteiros e a própria estrutura.

Checklist para implementação em C

  • Defina claramente qual campo será a chave.
  • Escolha o tamanho da tabela de forma coerente com a aplicação.
  • Implemente uma função de hashing adequada ao domínio da chave.
  • Planeje o tratamento de colisões.
  • Verifique o retorno de malloc().
  • Inicialize os ponteiros com NULL.
  • Libere toda a memória alocada.
  • Mantenha os nomes dos campos consistentes entre o cabeçalho e a implementação.

Conclusão

A tabela Hash é uma estrutura de dados voltada para associações rápidas entre chaves e valores. Sua principal ideia é trocar uma busca baseada em comparações por um cálculo que indique diretamente uma posição do array. O ganho de desempenho depende de uma boa distribuição das chaves e de um tratamento adequado das colisões.

Em C, a compreensão da tabela Hash também envolve conceitos importantes de modularização, tipos opacos, ponteiros, alocação dinâmica e gerenciamento de memória.
