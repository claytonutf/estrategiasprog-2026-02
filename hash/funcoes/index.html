01 · Ideia central

O que uma função de hash faz?

Na inserção e na busca em uma tabela hash, precisamos calcular em qual posição do array um elemento deve ficar. A função de hash recebe uma chave e produz um índice da tabela.

índice = h(chave)

Por exemplo, se a chave for a matrícula de um aluno, ela pode ser usada para calcular a posição onde os dados desse aluno serão armazenados.

Regra indispensável: a mesma função e os mesmos parâmetros devem ser usados tanto na inserção quanto na busca. Caso contrário, a busca pode procurar em uma posição diferente daquela em que o elemento foi inserido.
Objetivos de uma boa função

O que buscamos?

  • Rapidez: cálculo simples e barato.
  • Espalhamento: distribuir as chaves pela tabela de modo equilibrado.
  • Menos colisões: evitar que chaves diferentes caiam no mesmo índice, sempre que possível.
Não é possível garantir que toda chave diferente gere uma posição diferente em uma tabela comum. Isso depende do conjunto de chaves, do tamanho da tabela e da função utilizada.
02 · Método da divisão

Use o resto da divisão

É um dos métodos mais simples: divide-se a chave pelo tamanho da tabela e usa-se o resto como índice.

h(k) = k % TABLE_SIZE

Exemplo: chave 11

Com uma tabela de 10 posições:

11 % 10 = 1

O índice calculado é 1.

Exemplo: chave 21

Na mesma tabela:

21 % 10 = 1

O índice também é 1. Ocorreu uma colisão potencial.

Dica: escolher um tamanho de tabela primo pode ajudar a reduzir certos padrões desfavoráveis de colisão. Isso não elimina todas as colisões.

Implementação básica em C

// Pré-condições: TABLE_SIZE > 0 e chave não negativa.
#define TABLE_SIZE 10

int hashDivisao(unsigned int chave) {
    return (int)(chave % TABLE_SIZE);
}

O uso de um tipo sem sinal evita a questão de uma chave inteira negativa neste exemplo. Se as chaves puderem ser negativas, defina explicitamente como normalizá-las.

03 · Método da multiplicação

Multiplique e aproveite a parte fracionária

Multiplica-se a chave por uma constante fracionária A, com 0 < A < 1. Em seguida, a parte fracionária do resultado é multiplicada pelo tamanho da tabela; a parte inteira final é o índice.

h(k) = ⌊ TABLE_SIZE × frac(k × A) ⌋

Exemplo do material

  1. Chave e parâmetros: k = 123456, A = 0,618 e TABLE_SIZE = 1024.
  2. Multiplique: 123456 × 0,618 = 76295,808.
  3. Separe a parte fracionária: frac(76295,808) = 0,808.
  4. Multiplique pelo tamanho: 1024 × 0,808 = 827,392.
  5. Considere a parte inteira: índice = 827.
Em código real, a precisão de ponto flutuante pode afetar resultados próximos a limites. Para exemplos introdutórios, a conta ilustra o método; em aplicações, implemente e teste a fórmula escolhida com cuidado.
04 · Método da dobra

Dobre e some

O valor da chave é tratado como uma sequência de dígitos. Dobra-se a sequência para sobrepor partes e somam-se os dígitos correspondentes; o processo pode ser repetido enquanto o resultado ainda for maior que o tamanho da tabela.

O método também pode ser aplicado a valores binários. Nesse caso, a dobra combina grupos de bits usando OU exclusivo (XOR).

Exemplo binário

Chave 71, com k = 5

O número 71 é 0001000111 em binário. Dividindo em grupos de 5 bits:

00010 XOR 00111
= 00101
= 5

O valor calculado para a posição é 5.

05 · Strings como chave

Transforme texto em um valor numérico

Quando a chave é uma string e não há um identificador numérico disponível, é possível calcular um valor a partir dos caracteres. Somar somente os códigos ASCII, porém, ignora a ordem das letras.

“cama”

99 + 97 + 109 + 97 = 402

“maca”

109 + 97 + 99 + 97 = 402

As palavras têm letras em ordem diferente, mas a soma simples produz o mesmo valor. Uma abordagem descrita no material é multiplicar o acumulador por 31 e adicionar o próximo caractere.

valor = valor × 31 + caractere

Exemplo de função em C

unsigned long valorString(const char *texto) {
    unsigned long valor = 0;

    while (*texto != '\\0') {
        valor = valor * 31u + (unsigned char)*texto;
        texto++;
    }

    return valor;
}

#define TABLE_SIZE 101

int hashString(const char *texto) {
    return (int)(valorString(texto) % TABLE_SIZE);
}
O fator 31 ajuda a incorporar a ordem dos caracteres, mas não garante ausência de colisões. O tipo `unsigned long` também pode sofrer wraparound quando o valor ultrapassa sua capacidade; a função continua determinística, mas diferentes strings ainda podem gerar o mesmo resultado.

07 · Conceito fundamental

O que é uma colisão?

Uma colisão ocorre quando duas ou mais chaves diferentes produzem o mesmo índice. Por exemplo, com tamanho 10, as chaves 11 e 21 produzem o índice 1 pelo método da divisão.

11 % 10 = 1
21 % 10 = 1

Colisões são inevitáveis em tabelas comuns quando há mais chaves possíveis do que posições disponíveis. Uma boa função pode reduzir a frequência, mas a implementação também precisa tratar colisões.

Como lidar com colisões?

Estratégias comuns

  • Endereçamento aberto: procurar outra posição disponível dentro da própria tabela.
  • Sondagem linear: tentar sucessivamente posições seguintes, por exemplo `(posição + i) % TABLE_SIZE`.
  • Sondagem quadrática: calcular deslocamentos com termos quadráticos.
  • Duplo hash: combinar uma função para posição inicial com outra para o deslocamento.
  • Encadeamento separado: manter uma estrutura associada a cada posição para guardar elementos que colidem.
08 · Estratégia avançada

Hashing universal

Como uma função determinística pode ser explorada para produzir muitas colisões, o hashing universal seleciona aleatoriamente, durante a execução, uma função de uma família previamente definida.

h(k) = ((a × k + b) % p) % TABLE_SIZE
  • Escolha um número primo p maior que o tamanho da tabela e maior que qualquer chave válida, com 0 ≤ k < p.
  • Escolha parâmetros aleatórios válidos: tipicamente 1 ≤ a < p e 0 ≤ b < p.
  • Use os mesmos parâmetros durante a vida da tabela para que inserção e busca calculem a mesma posição.
Os limites dos parâmetros importam: usar `a = p` faria o coeficiente ser equivalente a zero módulo `p`. Por isso, a forma comum usa `1 ≤ a < p` e `0 ≤ b < p`.
09 · Perfeita ou imperfeita?

Hashing perfeito

Para o conjunto de chaves considerado, chaves distintas produzem posições distintas. É mais viável quando o conjunto de chaves é conhecido previamente, como em certos conjuntos fixos de palavras reservadas.

Hashing imperfeito

Existem pelo menos duas chaves distintas que produzem a mesma posição. A colisão não significa que a tabela esteja errada; ela exige uma estratégia de tratamento.

Em tabelas hash usuais, o objetivo prático é obter boa distribuição e manter as operações eficientes, além de tratar corretamente todas as colisões.
10 · Resumo em C

Uma implementação mínima

Este exemplo mostra o cálculo do índice pelo método da divisão. Ele não implementa uma tabela completa nem o tratamento de colisões.

#include <stdio.h>

#define TABLE_SIZE 10

int hashDivisao(unsigned int chave) {
    return (int)(chave % TABLE_SIZE);
}

int main(void) {
    unsigned int chave = 123;
    int posicao = hashDivisao(chave);

    printf("Chave: %u\\n", chave);
    printf("Posicao calculada: %d\\n", posicao);

    return 0;
}
Saída esperada:
Chave: 123
Posicao calculada: 3

Checklist para revisar sua implementação

  • O tamanho da tabela é maior que zero?
  • O índice calculado está entre 0 e TABLE_SIZE - 1?
  • A inserção e a busca usam a mesma função e os mesmos parâmetros?
  • Existe uma estratégia de tratamento de colisões?
  • O cálculo considera a natureza da chave (inteiro, matrícula, string etc.)?
